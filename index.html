Dwara · policy-controlled SSH access for AI coding agents

Give an agent a shell on your servers and it will eventually do something you didn't sanction. Dwara is an MCP server that sits between the agent and your hosts and treats the model as untrusted, so every guarantee lives in code rather than in the prompt. Named after the Dwarapala, the guardians at the doors of Indian temples.

  • 17 typed tools and no shell. Each tool has a zod schema and is named by risk class. There's no run_command, and commands are argv arrays escaped element by element.
  • Policy decides, not the model. Rules are set per host and per risk class (deny > require_approval > allow), and destructive actions are refused in code.
  • Transactional changes. Each change takes a snapshot, acts, checks that the fix actually held, and rolls back automatically if it didn't.
  • Humans approve; the agent can't. Approvals are single-use and bound to the exact action. 14 routes to self-approval are enumerated in the threat model, each with a test that closes it.
  • Server output is data, never instructions. Results are wrapped as untrusted, with detectors for injected instructions. Every action, refusals included, goes to a hash-chained audit log.
  • An open benchmark. 21 scenarios on a Docker lab: real faults, planted prompt injections, and unfixable cases where the right outcome is an honest handover. Runs are scored from the audit log, not the agent's account of what it did.
